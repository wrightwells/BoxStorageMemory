# Stage 11 verification

4 October 2026. Production packaging/security configuration and the [deployment/runbook](deployment.md) are delivered. Local and standalone HTTPS Compose examples preserve a private application port, environment configuration, health checks, restart behavior and no server inventory persistence. The application is a single multi-stage Node-build/Python-runtime image with hash-locked runtime dependencies, UID/GID 10001, read-only filesystem, temporary /tmp, dropped capabilities and no-new-privileges. The proxy has baked configuration and certificate-only named volumes, with no host config/Docker socket mount or privileged mode.

Security headers cover frontend/API/assets/errors and preflight: explicit CORS, configured HTTPS HSTS, CSP without application inline script/eval, nosniff, strict-origin referrer policy, popup-compatible COOP, frame denial and self-only camera/optional NFC permissions. Runtime browser schemas are compiled ahead of time and fixture parity is checked. The Google OAuth revocation endpoint is explicitly allowed. Optional interactive API docs use a separate hashed initialization-script policy and are disabled in production. Safe logging excludes bodies, sensitive queries, headers, raw paths and exception text; proxy request/exception logs are disabled.

App/proxy images build; production Compose and Caddy config validate. An isolated healthy non-root/read-only application passed compiled HTTP/API/OpenAPI checks. An isolated proxy passed CA-verified local HTTPS deep routes/HSTS and combined-log sentinel checks, then test resources were removed. Chrome/Firefox/mobile-layout browser tests pass final policies for synthetic authorization/revocation, Drive reads, JPEG blobs, QR labels, recovery/search and camera denial, with no principal-workflow CSP violations. These are not public certificate issuance, live Google consent, physical camera or two-account acceptance. The existing deployment was unchanged.

Deployment updates/rollback, safe diagnostics, Drive backup/restore, index preview/replacement gates and compatible-origin migration are documented. A synthetic restored library preserves identities/photo names with changed Drive IDs and rebuilt derived mappings; live restore/replacement saving remains gated. Writable production release approval is not claimed; see [release acceptance](release-acceptance.md).

The existing localhost service was subsequently updated and ten real single-account workflow checkpoints passed under these policies.
