# QR labels, scanning and optional NFC

Open a box and choose **QR label**. The page automatically generates the PNG through the token-free API and shows two bordered print previews: the permanent box number above the QR code, or to its left. Each preview has a print button below it that prints only the selected layout. Printed labels contain only the box number and QR code. Save QR PNG downloads the QR itself. Regenerate QR label refreshes both previews; failed automatic generation offers Retry QR label. Generation performs no Drive mutation and preserves UUID/number/folder identity. A printed QR grants no access; authentication and an accessible library root are still required.

Scan offers Start/Stop QR camera with video-only permission requested on a click. jsQR decodes bounded frames locally; no camera frame reaches the server. Camera tracks stop after a decoded result, explicit stop, navigation, sign-out/context change or hiding the page. Denial/no hardware leaves a pasted label URL, browsing, search and box-number lookup. Only the exact configured origin, canonical `/box/{uuid}` path and lowercase UUID are accepted. Plain text, another origin, query/fragment, trailing slash and encoded/normalized path tricks never redirect. The requested UUID survives sign-in/root selection; unknown/unavailable boxes produce errors without substituting another record.

Optional Web NFC requires `ENABLE_WEB_NFC=true`, a secure top-level context, NDEFReader, device permission and compatible hardware. Only a nonempty usable reader serial number counts; NDEF payloads never identify a box. An empty/malformed serial or unreadable tag reports failure. Known mappings are checked against recursively read authoritative inventories rather than trusted from a stale index. Duplicate/unreadable/incomplete inventories block a definitive lookup. Browsers without NFC remain usable.

Manage NFC tags from a box. Scan a serial to review unassigned/current ownership, choose whether to replace all this box's tags, and explicitly confirm. If assigned to another box, separately confirm moving it: old authority and derived index must be removed/verified first, then the new association is saved. Removal also requires review/confirmation. Partial steps are reported; interruption can leave the tag unassigned and never automatically replays either save. Re-read current mappings before another attempt. The box identity stays fixed. Production association/replacement/removal remain disabled by the existing Drive coordination gates.

UIDs normalize ordered 1–32 hex bytes to uppercase without separators. `04:aa:bb:cc` becomes `04AABBCC`; `CC BB AA 04` becomes `CCBBAA04`, a different UID. Do not reverse bytes heuristically. See [cross-client examples](client-integration.md) and [Chrome's NFC documentation](https://developer.chrome.com/docs/capabilities/nfc). Web NFC is NDEF-oriented and can return an empty serial; shared physical reference tags and a native reader are needed before claiming hardware interoperability. No native Android implementation is included.
